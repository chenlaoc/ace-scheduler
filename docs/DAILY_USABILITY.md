# 日常可用性实现记录

原交接基线为 v1.4.0；本文件记录后续分阶段实现，当时仓库为私有且未发布新版。v1.5.0 现已发布，维护者随后决定公开仓库；当前维护流程见 [维护与发布](RELEASING.md)。

## A. 恢复记录和退出（Issue #1）

`recovery.json` 保存在原配置目录，schema 1，包含系统启动时间、会话、PID/创建时间/名称，以及逐字段原值、最近写入值和确认状态。每次修改前使用同目录临时文件、flush/fsync、原子替换保存；记录失败则不执行该字段的新修改。写后回读并保存确认状态。

重新打开只观察。设置页提供安全恢复、明确覆盖冲突恢复，以及保留现值并归档记录三种入口。未确认写入和外部修改默认视为冲突；已恢复字段从记录移除，失败可重试。正常选择保留退出会归档记录；只读退出保留恢复机会。损坏/未知版本记录禁止新的写入，必须由用户明确归档；跨系统重启或超过 30 天的有效记录归档，不跨实例恢复。归档文件只保留证据，不自动再次加载。

退出弹窗防重入，排队操作与恢复继续等待后台回执；退出记录保存失败时窗口保留。原始恢复数据不会出现在 Git 或诊断导出中。

验证：117 项 Windows 本地回归通过（包含真实自建协作进程的跨会话恢复）；只读 smoke 和页面预览通过。证据在 `artifacts/recovery-smoke`、`artifacts/recovery-preview`。不承诺崩溃瞬间自动恢复，也不承诺抵御存储硬件未兑现刷盘的故障。

## B. 托盘与再次启动（Issue #2）

关闭偏好默认退出，可改为隐藏到托盘。托盘提供打开、停止全部规则（保留现值）、恢复原设置和真正退出。隐藏时继续采样/维护并积累有界历史，暂停图表和表格绘制；再次打开立即刷新。托盘不可用时显示窗口；长时间暂停后清除采样差分基线并重新检查维护。

单实例仍由 QLockFile 控制；随机名称的 QLocalServer 使用 UserAccessOption，只允许同一用户，并校验随机令牌和唯一固定的 activate 消息。第二实例收到确认后退出，不创建工作线程。通信有大小、连接数和时间上限。参见 [Qt 本机通信权限](https://doc.qt.io/qtforpython-6/PySide6/QtNetwork/QLocalServer.html)、[Qt 托盘重建行为](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QSystemTrayIcon.html)。

测试使用真正的第二个进程验证激活和令牌拒绝；不以同进程线程阻塞等待模拟跨进程通信。Explorer 重启由 Qt 托盘机制及可用性检查处理，本次没有重启用户的 Explorer 或改变系统睡眠状态。

## C. 按需提权（Issue #3，历史实现）

普通启动不请求 UAC，可观察、编辑和保存。点击需要写入的操作时才以 runas 启动完整管理员实例。接管文件只包含经过 schema 校验的 UI 配置/草稿/勾选/页面和实例身份，不传递命令或自动激活规则。两个实例必须属于同一 Windows 用户；用另一管理员账户输入凭据不受支持。

先准备管理员窗口，再停止原监控线程并移交 instance.lock；transfer.lock 阻止第三个启动者抢占交接，claim.lock 使最终接管与取消串行。取消 UAC、启动失败或超时保留原窗口和未保存草稿；正常接管不清理恢复记录。接管成功后仍只观察，并提示再次点击所需操作。实验采样从新会话重新积累。

测试覆盖取消、超时撤销、竞争锁、过期/身份变更/非法草稿，以及真正双进程的准备/交接/确认，确认没有创建第二个维护者或自动应用。双进程协议测试使用普通测试子进程，不冒充已完成安全桌面的 UAC 实测；实际允许/拒绝 UAC 及提权后的桌面焦点仍需人工验收。

## D. 异常、诊断与关于（Issue #4）

统一捕获未处理的 GUI/Python 线程异常，后台初始化/采样/维护的意外错误会停止两个计时器、撤销规则激活并显示持续错误状态。异常不会自动恢复或丢弃记录；设置中可重新启动后台，仍保持只观察。初始化部分失败、恢复时异常和线程意外结束均保留明确结果；失败状态下仍可明确保留现值并退出。

诊断 ZIP 在用户确认说明并选择位置后本地生成。包含程序版本/构建提交和是否有未提交改动、系统版本、CPU 拓扑数量、无规则名称的配置摘要、脱敏事件日志。采用字段白名单，不复制任意原始日志正文；仅保留时间、事件类别、调度字段及 WinError 代码。每个轮转日志最多读取 96 KB / 500 行，内存日志也受限。取消不生成文件，写出失败不替换原有 ZIP；不上传、不包含原始配置、恢复记录、个人路径、PID 或接管令牌。

关于页面可离线查看版本、构建、许可声明和配置位置；只有明确点击时才打开私有 GitHub Releases/Issues 或本地目录。更新入口是浏览器链接，没有自动更新、开机启动或签名承诺。

v1.5.0 Python 常量、Windows 版本资源、README 和 CHANGELOG 已同步。本地完整回归、只读启动和 100%/150% 原生窗口命中/缩放检查已执行；真实 Windows 托盘验证确认可用、隐藏后找回和真正退出。证据分别在 `artifacts/daily-tests.xml`、`artifacts/daily-smoke`、`artifacts/daily-window-*`、`artifacts/daily-tray-native` 和 `artifacts/daily-preview`。Qt 缩放测试不代表物理多屏 DPI 热切换。

## E. 启动权限调整（Issue #6）

按新的使用要求，普通启动改为在主窗口出现前申请管理员权限。已有实例先唤醒，UAC 取消后直接结束启动；授权后只观察，应用或恢复无需再次切换窗口。显式只读、版本查询和 smoke 保持不提权。EXE 继续使用 asInvoker 清单，由入口按启动参数决定是否请求 UAC，避免只读检查也要求权限。内部旧版交接协议保留兼容测试，不再用于普通启动。

启动分支使用独立子进程和模拟权限调用测试，覆盖普通启动、取消、失败、防循环、已有窗口、管理员、只读、smoke 和版本查询；不代表已执行真实 UAC 安全桌面验收。

## F. 亮色、暗色与自适应（Issue #7）

设置页新增外观选择，默认跟随系统，旧配置无需迁移。Qt 应用级调色板和样式覆盖页面、菜单、对话框；背景缓存、图表、窗口按钮和开关同步切换。配置保存失败时保留原主题，不触发调度操作。

系统外观监听采用 [Qt QStyleHints.colorSchemeChanged](https://doc.qt.io/qtforpython-6/PySide6/QtGui/QStyleHints.html)，在下一轮事件循环应用配色，避免被原生调色板更新覆盖。测试通过模拟 Qt 系统通知验证跟随和固定模式，不修改用户的 Windows 外观设置。

预览可用 `python -m tools.preview_ui --theme light` 或 `python -m tools.preview_ui --theme dark`；支持 `--output` 分开保存两组模拟截图。

完整回归包含启动权限各分支、主题保存/回退、系统通知、草稿保留与原有真实自建进程测试。另修复 Issue #8：关闭单实例服务时终止连接、停止超时计时器并交由 Qt 销毁，重复关闭安全。测试统一持有进程级 QApplication，并在每项结束后释放已关闭且无活动线程的窗口，避免全局换肤反复刷新测试残留对象。

最终本地 Windows 回归 **159 项通过、0 跳过**；证据为 `artifacts/preferences-tests.xml`。亮暗色均检查 1280×860 和 1040×700 预览，含 CPU 分配弹窗；只读启动通过。调度写入仍只针对测试自行创建的进程。
