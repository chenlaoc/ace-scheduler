## v1.0.0 初始功能与打包验证

- 环境：Windows x64，Python 3.13.2；CPU Intel Core Ultra 5 225H，psutil 与 Win32 API 检测为 14C / 14T，1 个 Processor Group。
- 53 项 pytest 通过，含真实 Windows API、GUI 后台线程启动和退出、应用中关闭窗口的时序、前后统计与真实子进程的发现/应用/维护/恢复链路。
- 真机子进程：Strong 的 Idle + 最后一个可用 CPU + EcoQoS ON，Default 的 Normal + 全 CPU + EcoQoS OFF，以及恢复原始系统管理状态，均成功并回读验证。
- 句柄验证：100 轮正常打开和伪造创建时间拒绝路径；最终句柄数没有增长。
- 单元覆盖：1/2/4/8/12/14/16/24/32/64 逻辑 CPU、动态 last1/last2/25%/50%/all/Mild、稀疏 ID、Custom 过滤及全无效、64 位最高位、多组拒绝、PID 重用、多同名实例、进程退出、AccessDenied 隔离、Apply Once、独立维护计时和失败退避、部分失败与恢复、EcoQoS 无关位保留、原子配置、损坏配置恢复。
- 源码 GUI：真实 Windows 启动，5 条默认规则，自动检测本机运行的 ACE-Tray.exe，始终仅监控；截图检查后修复深色系统主题对比度问题。
- 20.02 秒只读 GUI 基准：整机 CPU 平均 0.089%，单逻辑 CPU 口径 1.249%，工作集 145.50 MB，句柄 1169 → 1169，进程读写字节增量均为 0。该测量只有一个被监控实例，不代表所有机器/场景表现。
- 打包故障排查：首次运行在 QtCore 导入时失败，原因是构建环境 PATH 中 Poppler 的 ICU 78 被误收集，其导出为 `ucnv_open_78`，而 Qt 需要 Windows 系统 ICU 的 `ucnv_open`。已在 spec 中限定构建时 DLL 搜索目录；诊断包排除该冲突 DLL 后启动成功。
- 最终发布包：使用修正后的 spec 清理并重新构建；Windows GUI 子系统（PE Subsystem=2）、onedir。完整目录约 94.7 MB。从系统临时目录作为工作目录运行 EXE 的只读 smoke test，退出码 0、stderr 为空，Qt/后台线程初始化成功，检测到 5 条规则和一个 ACE-Tray 实例。截图已检查，所有主要控制与状态区域可见。实际证据在 `artifacts/packaged-final/smoke.json` 与 `window.png`。

构建命令：`.venv\Scripts\python.exe -m PyInstaller --clean --noconfirm ace_scheduler.spec`。运行测试：`.venv\Scripts\python.exe -m pytest -q`，最终结果 `53 passed`。源码和已打包程序的后台线程均可正常退出。

尚未做游戏运行下 SGuard64 的前后效果实验，也未对真实 ACE 应用任何调度策略。没有证实降低读取峰值；需要用户在相同场景下通过本工具继续测量。

4T~64T、稀疏 CPU ID 和 >64/多组限制属于模拟测试；实际机器为 14T。UAC 弹窗取消路径和不同受保护进程访问结果未在真人交互中逐一验证。旧版 Windows 的 EcoQoS 支持未实测，API 失败会显示而非假装成功。
