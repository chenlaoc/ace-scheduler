# 交互测试计划与执行记录

日期：2026-09-28。基线版本：1.3.0。测试对象：Windows x64 桌面应用、四个功能页面、无系统标题栏窗口、批量调度工作流。

## 执行原则

- 桌面测试：使用独立 APPDATA 启动已打包 EXE，以真实鼠标和键盘操作并检查窗口截图。
- 自动交互回归：通过 Qt 鼠标和键盘事件操作真实控件、模态对话框；对权限、磁盘失败、异步退出注入可控结果。
- Windows 接口测试：只写入测试自行创建的协作子进程，核对修改前、修改后及恢复后的实际数值。真实 ACE 只读。
- 所有配置、日志、CSV、截图和测试结果存放在 artifacts/interactive-20260928 下。用户现有配置和进程不作为写入测试对象。
- 通过条件：行为、落盘数据和调度读回一致；无崩溃、死锁、重复提交、误改未选规则；失败有提示且保留可恢复状态。
- 未执行的硬件或权限场景明确记为未覆盖，不用模拟测试冒充实机验证。

多显示器跨屏拖动、不同 DPI 显示器热切换、真实多 Processor Group 机器、UAC 安全桌面、真实 ACE 拒绝访问后的写入行为、长期游戏负载下的性能效果。模拟或只读结果不能替代这些实机结论。

## 执行结果

结论：本机计划范围通过。基线 79 项回归通过；新增交互测试首次有效运行为 14 通过、5 失败，对应下列三个产品问题。修复后完整回归 **103 通过，0 失败，0 错误，0 跳过**（新增 24 项）。修复发布版本为 **1.3.1**。

桌面操作使用 computer-use 的真实鼠标和键盘；Qt 回归用 QTest 驱动控件和真实模态对话框。二者分开统计，不把 103 项都称为桌面人工点击。

### 发现并修复的问题

| 问题 | 复现方式与原行为 | 修复及复测 |
|---|---|---|
| F01 间隔保存失败后状态不一致 | 设置页把采样从 1 秒改到 5 秒，注入磁盘写入失败；提示错误后内存及下拉框仍是 5 秒，磁盘保留 1 秒 | 先保存候选配置，成功才更新内存和工作线程；失败回退下拉框。继续修改维护间隔也不会把失败的值带入文件。对应 S02 通过 |
| F02 恢复全部未参与操作互斥 | 连点恢复全部产生两条命令；批量应用期间该按钮仍可点击；关闭不知道还有恢复进行中 | 统一忙碌状态、操作计数和结果回执；恢复时锁定调度入口及间隔设置。重复点击、恢复后排队退出、失败后退出重试均通过 |
| F03 恢复异常缺少完成信号 | 工作线程尚未就绪或恢复抛出异常时，没有 restore_done；恢复后退出可能一直等待 | 无论成功、未就绪或异常都发出一次明确结果，记录错误。失败保持窗口并允许重试；真实 QThread 恢复后退出通过 |

### 复现命令

```powershell
.venv\Scripts\python.exe -m pytest -q --junitxml=artifacts\interactive-20260928\regression-tests.xml
$env:ACE_TEST_ARTIFACT_DIR = "$PWD/artifacts/interactive-20260928/real-child"
.venv\Scripts\python.exe -m pytest tests/test_interactive_flows.py tests/test_interactive_windows.py -q
$env:QT_QPA_PLATFORM = "windows"
.venv\Scripts\python.exe -m tools.window_smoke --output artifacts/interactive-20260928/window-100
$env:QT_SCALE_FACTOR = "1.5"
.venv\Scripts\python.exe -m tools.window_smoke --output artifacts/interactive-20260928/window-150
Remove-Item Env:QT_SCALE_FACTOR
```

Qt 自动回归默认使用 offscreen 平台，不占用桌面鼠标；Windows API 子进程测试仍是真实接口。窗口脚本只检查自己创建的窗口。桌面交互记录为本次执行证据，未包装成依赖固定坐标的无人值守脚本。

### 本轮边界

没有应用真实 ACE 的调度设置，也没有得出游戏帧率或 I/O 改善结论。103 项通过表示列明的本机与故障注入范围通过，不代表其他 Windows 版本、多屏和保护进程全部通过。物理多显示器、DPI 热切换、UAC 安全桌面以及长期游戏负载仍需对应设备和场景实测。
